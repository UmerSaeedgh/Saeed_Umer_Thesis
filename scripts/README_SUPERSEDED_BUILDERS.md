# Do not regenerate notebooks 1 and 2

`build_notebook_1.py` and `build_notebook_2.py` are archived as `*.py.superseded`.
**Do not rename them back and do not run them.**

## Why

Notebooks 1 and 2 were subsequently revised directly, outside these builders, across several
rounds of external review. Those revisions are not reflected in the builder sources. Running
either script regenerates the notebook from the *older* builder content and **silently discards
the revisions** — the file is overwritten in place with no warning and no diff.

This happened once during the audit and was recovered only because a backup had been taken
minutes earlier.

The canonical artefacts are now the executed notebooks themselves:

| File | Status |
|---|---|
| `distribution_analysis_v1/00_corpus_and_sampling.ipynb` | canonical; still generated by `build_notebook_0.py` |
| `distribution_analysis_v1/01_foundations_and_baseline.ipynb` | **canonical; no builder** |
| `distribution_analysis_v1/02_persona_effects_and_conclusions.ipynb` | **canonical; no builder** |

All three are fully executed end to end, monotonically, with zero errors.

## What is still safe to run

- `build_notebook_0.py` — still the source for notebook 00, which has no external revisions.
- Every other script in this directory: `build_emotion_distributions.py`, `qc_gate.py`,
  `run_analysis.py`, `make_figures.py`, `make_tables.py`, `classify_ambiguity_pools.py` and the
  library modules. None of these write to notebooks 1 or 2.

## If notebooks 1 or 2 must be changed

Edit the `.ipynb` directly, then re-execute the whole notebook top to bottom:

```
jupyter nbconvert --to notebook --execute --inplace <notebook>.ipynb
```

A partial run leaves non-monotonic `execution_count` values, which means different cells were
evaluated against different kernel state and their outputs are not guaranteed to be mutually
consistent. Check afterwards that execution counts run `1..N` in order and that no cell carries an
error output.

## Why these files are kept rather than deleted

They document how the notebooks were originally constructed, including comments explaining several
analytical decisions that the notebooks themselves state only as conclusions. They are a
provenance record, not dead code.
